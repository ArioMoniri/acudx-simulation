## 1. Fixed in place (regression test next to each)

### F1. High. `/v1/voice/room` issued LiveKit room credentials to anyone, with a client-chosen identity and string-built JSON metadata
`server/voice/routes.py:120-137` (before). No dependency on the route; `identity` was taken from
the body; `metadata=f'{{"encounter_id":"{body.encounter_id}"}}'`.
Exploit: an unauthenticated caller who knows or guesses an `encounter_id` obtains a publish and
subscribe token for that learner's room (the room name is `sha256(encounter_id)[:16]`, so it is
derivable), can join as any identity (impersonate the learner or the patient agent), and an
`encounter_id` containing `"` injects arbitrary keys into the token metadata the agent worker
reads. Fix: `Depends(current_user)` (401 anonymous), identity bound to `learner-<user_hash>` with
the client value only as a suffix, `json.dumps` metadata. Tests:
`server/tests/test_voice_routes.py::test_room_token_is_signed_in_only_and_identity_is_bound_to_the_caller`,
plus `server/tests/test_route_guards.py` (see F5).

### F2. High. Every TTS and STT request launched (or waited on the boot of) the GPU worker even when a hosted provider was configured and serving
`server/voice/service.py:92-102` (before): `_candidates()` called
`resolver.resolve_worker(kind)` unconditionally before the registry rows were tried, and
`resolve_worker` calls `WorkerManager.ensure_worker()`, which launches a paid Lambda instance and
awaits readiness (up to `boot_timeout_s + ready_timeout_s`, 40 minutes by default).
Failure scenario: an institution with ElevenLabs configured and `LAMBDA_KEY` set pays for a GPU
on the first patient utterance and the first TTS response blocks until the worker is healthy.
Violates AGENT-PROTOCOL section 2.4 ("launched when a request needs them"). Fix: candidates are
now an async generator; the worker is asked for only after every registry row has failed or been
skipped. Tests: `test_voice_service.py::test_registry_provider_serves_without_launching_the_gpu_worker`,
`::test_gpu_worker_is_asked_only_after_every_registry_row_failed`.

### F3. Medium. The daily GPU budget was enforced only at launch; a worker kept busy ran past the cap
`server/providers/gpu_worker.py:345-351` (`_check_budget`) is called from `_launch` only; the
reaper (`reap_once`) looked at idle time alone. Scenario: budget 25 USD, A100 at 1.29 USD/h, a
class that keeps the worker touched for a day costs 31 USD and nothing stops it. Fix: the reaper
terminates with reason `budget` once `spent_today_usd() >= daily_budget_usd` (UTC day boundary, as
`_day_start` already defines it; the cross-midnight reset is intentional and documented). Test:
`test_gpu_worker.py::test_reaper_terminates_a_busy_worker_once_the_daily_budget_is_spent`.

### F4. Medium. A boot orphaned by a gateway restart was never terminated
`gpu_worker.py:421-434` (before): `reap_once` returned early for `status == "booting"` with the
comment "bounded by ready_timeout_s", which is only true while the in-process `_inflight` task
exists. After a restart the row stays `booting`, no request may ever arrive (`ensure_worker` is the
only path that re-attaches), and the instance bills until someone notices. Fix: a booting row with
no live `_inflight` watcher older than `boot_timeout_s + ready_timeout_s` is terminated with reason
`stale_boot`. The pre-existing boot-time test was rewritten on a real manager (it used a minimal
stand-in object that no longer matches the manager's surface). Test:
`test_gpu_worker.py::test_reaper_terminates_an_orphaned_boot_after_both_budgets`.

### F5. Medium. No test asserted that privileged routes carry a guard
New `server/tests/test_route_guards.py` enumerates `server.app:app` recursively (FastAPI 0.150
wraps included routers in `_IncludedRouter`, whose routes live on `original_router`) and asserts,
for 36 routes under `/admin/*`, `/v1/dean/*`, `/v1/faculty/*`, `/v1/voice/room`,
`/v1/events/encounter` and `/v1/me/*`, that `require_admin`, `require_guidelines_admin`,
`require_role("dean")`, `require_role("faculty")` or `current_user` is a declared dependency.
It also pins the mounted surface, so an un-mounted admin router fails loudly.

### F6. Low. `/admin/guidelines/verify` read `ADMIN_TOKEN` from `os.environ` only and ignored admin bearers
`server/guidelines/routes.py:103-109` (before). Inconsistent with `require_admin`
(`server/admin_routes.py:22-31`), which accepts the settings token or a verified admin JWT; an
OIDC-only deployment without `ADMIN_TOKEN` got a 503 from this one admin route. Fix:
`require_guidelines_admin` checks env, then `settings.admin_token`, then `bearer_admin`, keeping
the env path for the shell-run batch job. Covered by the existing
`test_tips.py::test_admin_verify_is_token_gated` and by F5.

### F7. Low (protocol). `@/data/mock` carried only types plus one static rail; comment noise hid real watchdog hits
`web/src/data/mock.ts` renamed to `web/src/data/schema.ts` (72 import sites rewritten by script,
`difficultyToTier` kept, `recommendedCases` moved to `web/src/pages/HomePage.tsx` as the
module-local `FALLBACK_RAIL` it always was). Comment-only hits that described non-mock content as
"mock" were reworded (`useLang.ts`, `EncounterPage.tsx`, `backend.ts`, `progressStore.ts`,
`startOptions.ts`, `landing.ts`). `scripts/watchdog.sh` now ignores the Tailwind `placeholder:`
variant, i18n keys named `*Placeholder` and the stepper's `"todo"` status literal. The two
offline self-test doubles in `server/rubric.py` and `server/case_generator.py` (`__main__` only)
carry `watchdog: allow` markers. Watchdog hits: 116 before, 24 after (see section 3).

## 2. Open findings (not fixed here; owner and proposed fix)

### O1. High. The GPU worker bearer token travels in a plaintext URL on port 80 for the worker's lifetime
`infra/gpu-worker/cloud-init.yaml:158-181` serves `/opt/acudx/public/diag/$WORKER_TOKEN/` over
`python3 -m http.server 80`, and `server/providers/gpu_worker.py:548-570` (`boot_log`) fetches
`http://{ip}/diag/{token}/...` from the gateway. The same token is the `Authorization: Bearer`
secret Caddy checks for `/v1`, `/tts` and `/stt` over TLS (`cloud-init.yaml:53`). Exploit: anyone
on the network path between gateway and worker (or a middlebox logging URLs) reads the token in
clear and gets unmetered use of the LLM, TTS and STT endpoints until the worker is reaped; the
`docker-status.txt` it serves also tails compose logs (`cloud-init.yaml:177`), which may echo
request bodies. Proposed fix (owner: AI engineer, infra): derive a separate diagnostics secret
(`sha256(token)[:32]`, computed in both `render_cloud_init` and `diag.sh`) so the bearer never
leaves TLS; stop the diag server once Caddy is healthy (or bind it to the gateway's egress IP via
the Lambda firewall rule); strip `compose logs` from `docker-status.txt` or cap it to container
health lines. Regression test: `test_gpu_worker.py` asserting the token string never appears in the
`boot_log` URL.

### O2. High (by design, needs a decision). In `AUTH_MODE=local`, dean and faculty are whoever says so
`server/auth/deps.py:149-162` (`_principal_from_headers`) builds the principal from
`X-User-Id` and `X-User-Role` with `verified=False`; `require_role` (`deps.py:200-210`) does not
distinguish. Every `/v1/dean/*` and `/v1/faculty/*` route (`server/learning/routes.py`) is therefore
open to any network peer in local mode, including cohort analytics, de-identified exports, grade
overrides (`/v1/faculty/review/{batch_id}`) and case approval. `/admin/*` is correctly exempt
(token or verified bearer only). This is the documented air-gapped default
(`docs/architecture/19`), so it is a product decision, but the default should fail closed.
Proposed fix (owner: fullstack engineer): in local mode let header principals hold at most
`resident` unless `X-Admin-Token` is also presented (operators seeding a classroom), or require
`verified=True` for `require_role("faculty")` and above; surface `verified_identity=false` in the
Dean and Faculty pages as a degraded banner (it is already in the API responses).

### O3. Medium. Learner memory and case checkpoints are readable and writable by id without authentication
`server/orchestration/routes.py:239-256` (`GET /v2/case/{thread_id}`), `:292-295`
(`GET /v2/learner/{learner_id}`) and `:262-289` (`POST /v2/director/step` with a body
`learner_id`). Any caller can read another learner's error profile and poison it. Proposed fix:
`Depends(current_user)` and derive `learner_id` from `user.sub`; faculty and above may pass an
explicit id within their org.

### O4. Medium. Ledger and worker status drift when the provider terminates a ready worker
`gpu_worker.py:518-546` checks the provider state only while `w.ip` is unset. A ready worker that
Lambda preempts or an operator deletes in the console stays `ready` in SQLite; `ensure_worker`
then enters `_wait_ready`, which polls `/healthz` for `ready_timeout_s` (25 minutes) before
terminating, during which every LLM request that needs the worker blocks, and the ledger books
cost until the idle or ready timeout rather than the real end. Proposed fix: in the readiness
loop and in `reap_once`, call `api.get_instance` every N polls and on
`terminated|terminating|preempted` close the ledger with `provider:<status>` and mark the row
`failed` immediately (the boot-phase branch at `:526-529` already does this).

### O5. Medium. The guideline verifier downloads whole documents before the size check and follows redirects anywhere
`server/guidelines/verifier.py:439-447`: `client.get(..., follow_redirects=True)` buffers
`r.content` fully, then compares against `MAX_BYTES` (25 MB). A publisher (or a hijacked
`fetch_url`) that streams gigabytes exhausts gateway memory; a redirect to a private address is
followed. URLs come from code-seeded rows, so this needs an insider or a compromised source.
Proposed fix: `client.stream("GET")` with an incremental byte cap, `max_redirects=3`, and refuse
a final URL whose host resolves to a private range unless `LOCAL_ALLOWLIST` names it.

### O6. Medium (protocol). The multiplayer room is still a shipped mock surface
`web/src/data/rooms.ts` (9 watchdog hits), `web/src/components/room/roomStore.ts:6`,
`web/src/lib/roomTransport.ts:5`: presence, floor control and closed-loop comms are projected from
static data with no server transport. It is honestly labelled in code but not in the UI as
degraded (AGENT-PROTOCOL section 2.1). Owner: fullstack engineer, roadmap Journey 6. Until the
transport lands, show a visible "simulated room, no other participants are real" notice.

### O7. Medium. Director steps are applied after Live mode is switched off and runtime creation races
`web/src/state/encounterStore.ts:887-905`: `runDirectorStep` checks `liveEnabled` before the
`await` but not after, so a slow answer that lands after `setLiveEnabled(false)` still mutates
the overlay and appends director notes to an offline encounter. `server/orchestration/routes.py:116-121`:
two concurrent first requests create two `OrchestrationRuntime`s (two aiosqlite connections, one
leaked). Proposed fix: re-check `liveEnabled` after the await; guard `get_runtime` with an
`asyncio.Lock` on `app.state`.

### O8. Low. `ProviderEndpoint.extra` is returned in full to the agent worker
`server/voice/routes.py` (`_agent_block`) strips only `seeded_from`; an operator who parks a
secret in `extra` of a TTS or STT row ships it. Admin-only, but the avatar branch already
filters key-like names; apply the same deny-list to every kind.

### O9. Low. `audience=""` disables the `aud` check silently
`server/auth/config.py:72-73` and `server/auth/jwks.py:149`. A misconfigured identity row accepts
tokens minted for any client of the same realm. Log a warning at config load and show it in the
admin identity panel.

### O10. Low. Admin token kept in `sessionStorage`
`web/src/components/admin/adminSession.tsx:30`. Acceptable for an operator console (tab-scoped,
not persisted), but any XSS in the admin bundle exfiltrates it. Prefer the verified admin bearer
(already supported by `require_admin`) and drop the token path once OIDC is on.

### O11. Low. SSE streams have no server-side duration cap
`server/orchestration/routes.py:191-216`: a stuck graph node keeps the connection and the
checkpoint write loop alive until the client disconnects. Add an `asyncio.timeout` around the
`astream` loop (for example 180 s) that emits an `error` event.

## 4. Verified clean (no finding)

* Secrets: `ProviderRecord.public()` excludes key and ciphertext (`registry/store.py:112-117`);
  `WorkerRecord.public()` excludes the token; no `log.*` call formats a key or token; identity
  `public()` carries only the PKCE client id.
* Fernet: a missing `ACUDX_SECRET_KEY` refuses to persist (`SecretKeyMissing`), never plaintext;
  env-seeded rows resolve keys from env at call time.
* JWT: `alg` is allow-listed to asymmetric algorithms before `jwt.decode` and the header `alg` is
  passed as the only accepted algorithm (no `none` or HS confusion); `iss`, `exp`, `iat`, `sub`
  required; one JWKS refresh on unknown `kid`.
* SQL: every f-string column list comes from code-owned kwargs or a fixed whitelist; values are
  bound parameters.
* File serving: no `FileResponse` or `StaticFiles`; the imaging bank returns URLs, not paths.
* Results engine units: kinetics outputs are converted where the reference table differs
  (glucose mmol/L to mg/dL at `results/engine.py:436`); troponin ng/L, lactate and potassium
  mmol/L, procalcitonin ng/mL, creatinine mg/dL already match `reference_ranges.json`.
* Live order path: the engine promise and the playback timer are joined in `resolveOrder`
  (`encounterStore.ts:607-626`); a second resolution is a no-op through the `!o.resolved`
  checks; the Director overlay is clamped in `clampDirectorVitals` and deltas bounded per key.
* Orchestration honesty: `/v2/case/generate` answers 503 `model_unreachable` or 502
  `model_output_invalid`, never a template; the template is its own route with
  `meta.source="template"`. A safety veto with exhausted repairs applies deterministic overrides
  and marks the case degraded before `finalize`.
* Voice failover: hosted rows in priority order, language-aware skipping, one telemetry row per
  attempt, metered streams close the row on error.
