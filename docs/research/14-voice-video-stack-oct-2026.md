# 14 - Realtime Voice + Video Patient Stack (October 2026 refresh)

**Scope.** The learner talks to an AI patient by voice and sees a lip-synced face on a video-call tile inside the Epic-like EHR. This doc re-surveys, as of 2026-10-19, (1) hosted realtime avatar APIs, (2) self-hostable open talking-head models that fit one Lambda A100/H100, (3) STT / TTS / speech-to-speech options with Turkish support, (4) orchestration frameworks, and (5) a recommended primary + fallback architecture with per-interview cost. It supersedes the price snapshots in `02-voice-ai.md`, `10-realtime-avatars-2026.md` and `12-realtime-talking-avatars-2026.md`; the tiering decisions in `12` (T0 client 3D default, T1 self-hosted, T2 premium API) still stand and this doc fills in the T1/T2 vendors and numbers.

**Method and caveats.** Every number below carries the URL it was read from. Vendor pages were fetched directly where possible; where a vendor page was unreachable (HeyGen LiveAvatar pricing, D-ID API pricing, Hedra pricing all returned 404 or empty shells on 2026-10-19) the figure comes from a dated third-party index and is marked **[unverified]**. Several sources are competitors writing about each other (Spatius, Selvia, Akapulu, HeyGen blog); they are used only for numbers that two or more sources agree on, and flagged otherwise. Prices are USD, pre-tax, and will move.

**What AcuDx is already running (repo state).** The dev server proxies ElevenLabs TTS (`POST /tts`) and ElevenLabs STT (`POST /stt`) from `web/vite.config.ts`, with the browser wrappers in `web/src/lib/tts.ts` and `web/src/lib/stt.ts` (request/response, not streaming). The Python gateway (`server/config.py`, `server/model_gateway.py`) has an `LLM_PROVIDER = local | api` switch and an `AIRGAPPED` egress guard that refuses non-local endpoints at resolution time. There is no voice or avatar provider switch yet; section 5 proposes one that reuses the same pattern.

### 1.2 LiveKit-hosted avatar integrations

LiveKit Agents lists 16 avatar providers: Anam, Avatario, AvatarTalk, Beyond Presence, bitHuman, D-ID, Keyframe, LemonSlice, LiveAvatar, Protoface, Runway, Simli, Spatius, Synthesia, Tavus, TruGen. Python and Node: Anam, Beyond Presence, D-ID, LemonSlice, Protoface, Runway, Tavus, TruGen. Python only: Avatario, AvatarTalk, bitHuman, Keyframe, LiveAvatar, Simli, Spatius, Synthesia ([docs.livekit.io/agents/models/avatar](https://docs.livekit.io/agents/models/avatar/)).

Wiring is identical for every provider, which is what makes provider switching cheap: build `AgentSession(stt, llm, tts, ...)`, create `provider.AvatarSession(...)`, `await avatar.start(session, room=ctx.room)`, `await avatar.wait_for_join()` (30 s default timeout), then `session.start()` with audio output disabled. The agent's audio is routed to the avatar worker, which joins the room as a second participant publishing synced audio+video, tagged `lk.publish_on_behalf`; React `useVoiceAssistant` picks the right tracks. Every plugin emits `AvatarMetrics` (join latency, playback latency) on `metrics_collected` ([same page](https://docs.livekit.io/agents/models/avatar/)). A custom self-hosted renderer plugs in through `AvatarRunner` (Python), which is the hook for the open-source fallback in section 2.

Pipecat lists HeyGen, LemonSlice, Tavus and Simli under Video services ([pipecat README](https://github.com/pipecat-ai/pipecat)).

**How the realtime ones do it.** MuseTalk and wav2lip skip generation and only inpaint the mouth region of pre-recorded frames, one UNet pass per frame, with the avatar's latents cached at preparation time. LiveTalking adds a producer/consumer loop that decouples GPU inference fps from output fps and pushes frames to aiortc WebRTC ([LiveTalking](https://github.com/lipku/LiveTalking)). Ditto and LivePortrait-family models run a small motion generator in a keypoint space and a cheap warping renderer (about 15 ms per frame on a 4090) ([speed.md](https://github.com/KwaiVGI/LivePortrait/blob/main/assets/docs/speed.md)). SoulX-FlashHead reaches realtime with a 1.3B distilled autoregressive video diffusion model plus an audio context cache and oracle-guided distillation to keep identity stable over infinite length ([arXiv 2602.07449](https://arxiv.org/abs/2602.07449)).

## 5. Recommended architecture

### 5.1 Topology

```
browser (EHR shell, video tile)  <-- WebRTC -->  LiveKit server (self-hosted, Apache-2.0, or LiveKit Cloud)
                                                     |
                                           livekit-agents worker (Python 1.8.x)
                                             AgentSession(stt, llm, tts, vad=Silero, turn=audio v1-mini)
                                             AvatarSession(provider)   <- chosen by admin panel
                                                     |
            +----------------------------------------+----------------------------------------+
            | PRIMARY (hosted, network-connected)     | FALLBACK (self-hosted, air-gap capable)  |
            | face: Anam or Simli (LiveKit plugin)    | face: LiveTalking+MuseTalk 1.5 or         |
            | STT: Deepgram Nova-3 tr / Scribe v2 RT  |       SoulX-FlashHead Lite via AvatarRunner|
            | TTS: ElevenLabs v4 Turbo / Flash        | STT: faster-whisper large-v3-turbo         |
            | LLM: existing gateway (local or api)    | TTS: Chatterbox Multilingual V3 (tr)       |
            |                                         | LLM: llama-server Qwen2.5-7B (existing)    |
            +-----------------------------------------+--------------------------------------------+
                                                     |
                                     T0 always available: client-side 3D head + visemes (doc 12)
```

Why this shape: the agent worker, the WebRTC room, the turn detector and the EHR front end are identical in both paths; only the plugin classes differ. LiveKit's `AvatarSession` contract and `AvatarRunner` for custom workers ([avatar docs](https://docs.livekit.io/agents/models/avatar/)) let the open renderer appear to the browser as the same `lk.publish_on_behalf` participant as Anam or Simli would. The T0 client-rendered 3D patient from `12-realtime-talking-avatars-2026.md` remains the universal degrade target when no video track arrives within `wait_for_join()`'s timeout.

Why Anam first, Simli second, Tavus third for the hosted face: Anam is the cheapest managed stack with a self-serve path to $0.11/min and a BYO-audio mode so our own STT/LLM/TTS and Turkish voice stay in our control ([anam.ai/pricing](https://www.anam.ai/pricing), [anam docs](https://anam.ai/docs/)); Simli is render-only at $0.01/min with LiveKit and Pipecat plugins ([simli.com/pricing](https://www.simli.com/pricing)); Tavus has the best rendering model and confirmed Turkish but costs $0.26 to $0.35/min and gates HIPAA/ZDR behind Enterprise ([tavus.io/pricing](https://www.tavus.io/pricing)). HeyGen LiveAvatar LITE is a price-competitive alternate once its pricing page is readable again. D-ID is 3 to 5x the price of Anam and Hedra realtime is gone.

### 5.2 Wiring the admin panel to switch providers

Extend the existing `Settings` in `server/config.py` and the egress guard, do not build a parallel mechanism:

1. Add enums next to `llm_provider`: `avatar_provider: Literal["none","client3d","musetalk","soulx","anam","simli","tavus","liveavatar"]`, `stt_provider: Literal["browser","whisper_local","deepgram","elevenlabs","openai"]`, `tts_provider: Literal["browser","chatterbox_local","elevenlabs","deepgram","openai"]`, `voice_mode: Literal["cascade","realtime_s2s"]`, plus per-provider `*_base_url` / `*_api_key` fields. Every hosted value resolves to a non-local URL, so `AIRGAPPED=true` already rejects it at resolution time; only `client3d`, `musetalk`, `soulx`, `whisper_local`, `chatterbox_local`, `browser` pass the guard.
2. Persist institution-level overrides in the DB (an `institution_provider_policy` row: allowed providers, monthly minute cap, Turkish required flag, data-residency flag). The admin UI (`web/src/pages/InstitutionPage.tsx` is the natural home) shows the matrix, the live `reachability()` probe result per provider (reuse `ModelGateway.reachability()`), and the current month's spend from the metering table.
3. Expose `GET /admin/providers` (effective config, probe status, capability flags such as `turkish_tts`, `hipaa_available`, `self_hosted`) and `PUT /admin/providers` (validated through `Settings`, audit-logged). The agent worker reads the effective policy at session start and instantiates `stt`, `tts` and `AvatarSession` by name from a registry dict; nothing else changes.
4. Fallback ladder at runtime, evaluated per session: hosted avatar join fails or `AvatarMetrics.join_latency` exceeds the budget -> switch to the self-hosted `AvatarRunner` if the GPU pool reports capacity -> else T0 client 3D. STT/TTS fall back the same way (hosted -> local -> browser Web Speech). Each hop emits a metering event so cost reports show which path served the minute.
5. Meter everything in agent-session minutes and provider-billed units (STT minutes, TTS characters, avatar minutes, GPU seconds). Tavus bills in 6 s increments with a 30 s minimum ([tavus pricing](https://www.tavus.io/pricing)); Anam and HeyGen in whole minutes or credits; keep per-provider rounding rules in the metering code, not in the UI.
6. The browser side (`web/src/lib/tts.ts`, `stt.ts`) becomes a LiveKit client; the current `/tts` and `/stt` dev proxies stay as the `browser` fallback provider only.
